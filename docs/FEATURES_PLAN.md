# План новых функций H1–H7 (на будущее)

Статус: **план, не утверждён к реализации** (2026-10-19). Владелец выбрал пункты из списка идей «вау-функций»
для людей, не знакомых с трейдингом, и попросил расписать план. Начинать только **после завершения золота (G5)** и
только после «да» владельца по каждому этапу (как всегда: план → «да» → код → тесты → коммит → отчёт).

Общее правило для всех функций: ни одна не должна создавать впечатление, что ARVEN «печатает деньги»
(CLAUDE.md, правило 6). Тяжёлые расчёты считаются заранее скриптами, сайт только показывает готовое.

|---|---|---|---|
| H1 | Обратный отсчёт до новостей | 1–2 дня | — |
| H2 | Живой глобус торговых сессий + карта активности по часам | 2 дня | — |

Открытые вопросы владельцу: порядок этапов; matplotlib для H5.

## H1. Обратный отсчёт до новостей

- **Видно:** «До решения ФРС 1 д 3 ч 12 мин» и как обычно двигались BTC и золото в первые 15/60/240 минут после
  такого события (средний размах, медиана, худший случай). В Telegram — напоминание за час.
- **Устроено:** календарь FOMC/CPI/NFP уже есть (`config/macro_events.csv`). Новый расчёт движения после прошлых
  событий по 1m-данным (обновление раз в день), API `/api/events`, карточка на сайте, напоминание через outbox.
- **Честность:** статистика прошлого, не прогноз; «размах, а не направление».
- **Тесты:** расчёт без заглядывания в будущее, UTC и переход на летнее время, пустой календарь.

## H2. Глобус торговых сессий

- **Видно:** вращающаяся Земля с днём/ночью, горят открытые центры (Сидней, Токио, Лондон, Нью-Йорк); статус
  «Золото: торгуется / пауза / выходные, откроется через …», «BTC: 24/7». Под ним тепловая карта: в какие часы и дни
  рынок движется сильнее.
- **Устроено:** календарь сессий уже есть (`arven.core.sessions`); API `/api/sessions`; глобус на `<canvas>` без
  внешних 3D-библиотек; карта — средний размах 1h-свечи по часу и дню недели.
- **Тесты:** статус в моменты переходов (пятница 17:00 Нью-Йорк, DST, праздники); Lighthouse ≥ 90; телефон.

## H3. «1000 параллельных вселенных»

- **Видно:** веер из 1000 счетов «случайных трейдеров» (те же стопы и цели, случайные моменты входа) и поверх —
  линия стратегии; итог вида «S7 на validation лучше 38 % случайных трейдеров — это удача, а не умение». Выбор
  стратегии, рынка, периода.
- **Устроено:** контроль случайных входов уже считается (`random_control`); сохранять кривые (прореженные до ~200
  точек) в `data/markets/<рынок>/research/universes/`; сайт только рисует (`<canvas>`, анимация). Фиксированный seed.
- **Тесты:** воспроизводимость; процентиль совпадает с числами опубликованных отчётов.

## H4. Машина времени

- **Видно:** выбор рынка, даты, стратегии (готовые сценарии: «Ковидный обвал, март 2020», «BTC $69 000, ноябрь
  2021», «Золото $2000+, 2024»); график проигрывается как видео (▶ ⏸, ×1…×1000); на глазах появляются линия, пробой,
  Фибоначчи, вход, стоп, цели, частичные закрытия; сбоку счёт $1000 и лента событий простыми словами.
- **Устроено:** экспорт «шагов» — что стратегия знала в каждый момент (сетап S7 появляется только в момент взведения:
  никакого заглядывания в будущее даже в анимации), заранее по сценариям; свечи из `/api/candles`; плеер на базе
  `CandleChart` (lightweight-charts); тексты событий — шаблоны из посчитанных данных, без LLM (правило 9).
- **Тесты:** ни один элемент не появляется раньше своего времени (тест на утечку будущего в плеере); конечный счёт
  сценария = отчёт; плавность ×1000 на телефоне.

## H5. Сигнал в Telegram картинкой

- **Видно:** PNG графика со свечами, линией/зоной стратегии, входом, стопом, TP1–TP3 и подписью
  («GOLD XAUUSD · LONG · S7»); обновления (TP, стоп) тоже картинкой.
- **Устроено:** рисование на сервере — **matplotlib (новая зависимость, только с разрешения владельца)**; отправка
  `sendPhoto` тем же клиентом и outbox; если картинка не получилась — обычный текст (сигнал не теряется).
- **Тесты:** цены на картинке = цены в тексте; запасной текст; поддельный сервер Telegram; файл < 1 МБ.

## H6. Приложение на телефон (PWA)

- **Видно:** «Добавить на главный экран» → иконка ARVEN, полноэкранное приложение, последние данные без сети
  (с пометкой «офлайн»).
- **Устроено:** манифест, иконки, service worker (кэш оболочки и последних ответов API), без зависимостей.
  **Пуш-уведомления требуют HTTPS-адреса, доступного с телефона, то есть сервера** — после переезда на
  Oracle/VPS; до тех пор их заменяет Telegram.
- **Тесты:** Lighthouse PWA, офлайн, установка на Android (Chrome).

## H7. Лаборатория гипотез (большой этап)

- **Видно:** страница «Лаборатория»: стратегия из блоков (условия входа, стоп, цели, фильтры — тренд 4h, время суток,
  сессия, новости) → «Проверить» → честная проверка (development → validation → forward → случайные входы → стресс
  издержек) и вердикт простыми словами («похоже на удачу» / «не опровергнуто, нужна живая проверка»); понравившуюся
  гипотезу можно отправить в живые сигналы как EXPERIMENTAL.
- **Устроено:**
  1. JSON-схема блоков (только готовые признаки, пороги, уровни — стратегия как данные, не как код);
  2. один исполнитель JSON → `SignalProvider` (тот же путь, что S4–S6: бэктест и живые сигналы одним кодом, правило 8);
  3. автоматическая честная проверка: development для настройки, validation **один раз** на гипотезу с записью в
     журнал, **счётчик всех попыток** (видно, сколько вариантов перебрано), запечатанный тест из лаборатории недоступен;
  4. фоновая очередь задач с прогрессом на сайте;
  5. позже: ИИ переводит текст/статью в черновик блоков («ARVEN учится по материалам»); ИИ только предлагает,
     проверяют код и данные (правило 9).
- **Главный риск:** перебор сотен вариантов всегда находит красивый случайный бэктест — поэтому счётчик попыток и
  одноразовая validation обязательны.
- **Тесты:** JSON-стратегия = вручную написанная стратегия того же смысла; утечки будущего; правила одноразовой
  validation и запрета на запечатанный тест.

## Ограничения

- Ноутбук (7,2 ГБ памяти) с трудом тянет даже загрузку данных: тяжёлое считать заранее; для постоянной работы и
  пушей нужен сервер (`docs/DEPLOY_SERVER.md`).
